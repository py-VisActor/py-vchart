# 逐图迁移与验收规程

适用于[静态移植计划](PORTING_PLAN.md)中的每个图种。以下目录、比较规则和工具是实施约定；首批基准与比较器在批次 0 建立。

## 一次迭代的单位

一次迭代选一个图种的一组可观察行为，例如“bar 的正负值与零基线”。按 `计划中 → 已取上游基准 → 实现中 → 已验收` 跟踪到变体粒度。基准无法复现时记为阻塞，尚缺静态功能记为部分支持，范围外字段记为忽略。状态表逐项记录图种、变体、上游版本和路径、所需 _deps 能力、案例 ID、最近报告与未覆盖项。

1. **定范围。** 从注册方法追到 transformer、series、mark、组件和数据变换。列出必需字段、缺省行为、支持的样式和排除的动态字段。挑一个上游已有的典型例和一个容易“图看着差不多但数据错了”的边界例。
2. **先取基准。** 在独立的开发环境用固定上游和相同 spec 生成数据、几何与 PNG。记录实际加载的包版本、上游提交、资源哈希和渲染参数。标准出图入口为[无头浏览器原生 PNG 导出工具](../tools/oracle/README.md)，以固定浏览器构建调用 getDataURL()，生成 expected.png。其他 Node 离屏入口可参考[上游 line-chart.js](https://github.com/VisActor/VChart/blob/fdb63276cf8b71f5a6cca128c409e009cc94615a/packages/vchart/__tests__/runtime/node/line-chart.js)。先确认执行的是固定检出的构建产物；Node 和上游 JS 仅用于制备基准。
3. **做最小完整实现。** 从公开 Python 入口读取原始 spec，经过 transformer、数据视图、比例尺或专用布局、图元和后端。新增共享能力应带独立测试和消费方。不得按案例 ID、固定坐标或参考图分支。
4. **逐层定位差异。** 依次比标准化配置、派生数据、比例尺、布局、图元和图像。首个不一致的层决定修复位置。例如柱体高度错误先核对数值域和零点；几何相同而文字不同，再核查字体文件、字号、基线与后端。
5. **回归与登记。** 修复前保留失败用例，修复后从同一个候选版本运行本图种、共享模块消费者和累计全部静态用例。登记实测通过的变体、证据位置和未覆盖选项。移交下一图种时写明可复用模块及已知限制。

## 用例怎样创建

每个案例目录建议包含以下受版本控制的文件。生成的候选结果、差异图和报告存入独立运行目录。

```text
tests/cases/bar/signed-baseline/
  case.json          # ID、来源、覆盖行为、环境配置引用、比较规则
  spec.json          # 两端使用相同输入；大数据与资源通过相对路径引用
  expected.scene.json
  expected.png
test-runs/<run-id>/bar/signed-baseline/
  actual.scene.json  actual.png  diff.png  result.json
```

**可直接实施的首例。** 输入宽 400、高 240、DPR 1、animation=false，具名数据 sales 为 Jan=8、Feb=−3，xField=month、yField=value。完整 JSON 见[架构分析中的柱图样例](VCHART_ARCHITECTURE.md)。保留缺省轴以覆盖 transformer。在场景快照上断言两根柱按 Jan、Feb 排列，同享 y(0)；Jan 柱位于零线上方，Feb 柱位于下方。以实际数值轴的 domain/range 核对两端坐标。缩窄宽度的派生案例应保持数据域，重新求分类带宽。再加一个仅切换 hover 或动画配置的用例，比较 Python 静态结果是否一致。

| 用例族 | 构造方法 | 核查对象 |
| --- | --- | --- |
| 默认与显式配置 | 从上游最小例开始，每次只改一个字段，再补一个有意义的组合 | 默认值、覆盖优先级、图例或轴的占位 |
| 数据边界 | 按上游实际支持行为构造空集、单值、零、负数、重复类别、缺失值和极端范围 | 数据顺序、有效图元数、断点、零点及域 |
| 图种特有 | bar 的分组或堆叠、pie 的内半径、sankey 的分流、map 的孔洞 | 每个变体至少一项数值或拓扑断言及一张基准图 |
| 跨层与回归 | 小画布与长中文标签、共用比例尺的双系列、替换数据或尺寸后重新渲染 | 裁剪和文字边界、重复渲染与新实例结果等价 |
| 负例与范围 | 非法字段、未知 type、未支持的静态分支、被忽略的动态配置 | 异常类别及字段路径，或静态结果等价；按实际输入契约区分 |

固定本地数据、字体和许可允许纳入的地图/图片；随机布局固定种子与算法。两端应使用相同的输入次序、主题、尺寸、DPR、背景、语言、时区和字体文件。若上游未暴露随机种子，先在参考环境固定随机源并验证重复性，仍不稳定的案例标为阻塞。上游测试可用于提炼配置和断言，例如[柱图单测](https://github.com/VisActor/VChart/blob/fdb63276cf8b71f5a6cca128c409e009cc94615a/packages/vchart/__tests__/unit/chart/bar.test.ts)；来源中的 DOM 辅助函数不进入 Python 项目。

## 基准、图片对比与判定

1. **可信基准。** 每次制备在相同设置下运行上游两次。比较去除运行时 ID 的场景和解码后图像；不一致时查字体、时钟、随机源和后端。基准由固定上游生成或由来源明确的人工断言补充，禁止把 Python 当前输出写成上游预期。普通测试只读基准。更新基准需单独记录原因、环境差异及新旧对照。
2. **比较几何。** 场景按区域、系列、数据键和图元角色定位，同时保留绘制次序。比较记录数、文本、颜色、几何、裁剪和层级。枚举、数量、文字、颜色及顺序精确比较。浮点先采用绝对误差 1e−6 个逻辑像素作为确定性算术的起始约定；字体度量或算法近似需以具体字段和案例单列容差。坐标系和单位统一后再比较。
3. **比较图像。** 两端输出原尺寸 PNG，先比尺寸，再解码为相同颜色空间、相同 alpha 表示的 RGBA；约定全透明像素 RGB 归零，保留 alpha 差异。每像素记录最大通道差，统计差异像素数、占比、最大差及差异包围盒。默认精确比较。独立记录每个关键区域（如柱体、刻度、标签）的指标，防止一根细线或一个负号被全图平均值淹没。禁止自动缩放、平移或模糊图像后判定通过。
4. **跨后端差异。** 先用纯色矩形、细线、文本和半透明重叠校准。确认为抗锯齿或字体栅格化差异后，才为指定环境和案例登记最大通道差、允许超限像素数和区域，保留对照图片及原因。阈值须能拦截删除图元、错色与位移等故障注入。文字内容、关键几何和图元数始终独立验收，禁止批量放宽阈值或遮盖整块文字。
5. **判定与报告。** 任一基准缺失、环境指纹不符、捕获失败、关键断言失败或像素指标超限，该用例均不能通过。每次保留上游图、候选图、放大的局部和差异热图的可定位路径，报告给出两端版本、spec/基准哈希、命令、退出码、指标及首个失败层。报告区分通过、失败、阻塞与范围外。人工复核解释残差；涉及豁免时应记录理由及适用环境，让后续运行能够重现判定。

## 合入条件

- 从项目既有测试入口发现并运行新增单测；使用标准库 unittest 时，嵌套测试包按支持的 Python 版本配置发现，并核对运行清单中的案例 ID。
- 正常安装后可通过公开入口，从同一份 spec 实际生成图片。几何单测、逐图用例、共享模块消费者与累计回归均有结果。
- 依赖迁移记录、支持表和报告对应同一个候选版本。检验发行包只携带运行时需要的模块和资源，固定上游、截图工具及测试产物留在开发侧。
- 同一输入在约定环境重复运行可复现。若只完成一个变体，登记该变体已验收，并列出同类型剩余任务。
